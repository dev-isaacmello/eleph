## 0.4.0

### 新增

* **一个 MCP 服务器**（`eleph-mcp`，在 `mcp` 额外依赖之后）。四个工具，全部无状态，都不碰磁盘也不碰网络：`eleph_check` 消解每一条义务并返回推翻规则的那段历史；`eleph_obligations` 打印这些条件而不去消解；`eleph_simulate` 把一串事件重放穿过一个守卫，并报告它拒绝了什么；`eleph_declarations` 列出一份策略声明了什么，每条事实都展开成它所代表的公式。

  它有意提供检查器而不是文档。一个只会背文档的服务器，会让模型凭记忆写出一份策略并未经验证地交出去，而那正是这个项目存在要阻止的失败。

* **一个 skill**，给使用 eleph 的人的编程助手。它承载「写—检查—修」的循环，以及那些意味着某条规则无法表达的局限，让模型停下来而不是去近似。

* **这个仓库本身是一个插件市场**，所以装好两者是两条命令，而不是一次克隆加一次复制。见[配合你的编程助手](/docs/use/with-your-assistant)。

### 修复

* 本文档里有三十三条事实声明被折成了多行，而那不能解析：一条 fact 的主体不能跨行，而文法页在三种语言里都说了相反的话。现在有一个 CI 步骤会把本站印出的每一个程序交给 `eleph check`。

## 0.3.0

### 新增

* **数值字段**，在事件发生的那一刻比较：`charged(U, amount > 100)`。这个比较是原子身份的
  一部分，而不是一条可能在底下移动的独立事实，所以完备性论证得以保住，数值程序仍然是被
  穷尽判定的。
* **权限**，McCarthy 的第八种言语行为：
  `on question(Q, saldo(U)) permitted autorizado(Q, U):`。不是回答是否为真，而是这一方
  是否有资格发问。权限进入路径条件，所以回答是在它之下被证明的，而运行时失败时是闭合的。
* **要约**：`offer C that φ`，最弱的一种承诺。它不是债务，因为没有人接受它；它所欠的是
  存在某条路径可能兑现它。
* **一项针对没锁的门的结构性检查。** 一个处理器要求权限而它旁边那个什么都不要求，就是锁好
  的前门旁边开着一扇窗，现在会被报告为缺陷。
* **一个完整的 LangChain 示例**（`examples/langchain-agent`）：同一个智能体在九个场景上
  分别以带守卫和不带守卫运行，对接 Claude，可用 API key 或经由 OAuth 的 Agent SDK。

### 修复

* 每一条被声明的事实都会做类型检查，无论有没有被调用。解析原本是惰性的，所以一条没有任何
  处理器提到的事实，根本不会被检查。

## 0.2.0

首个公开版本。

### 新增

* **可嵌入的 Python API**（`eleph.Policy`、`eleph.Guard`）。三种集成形态：observer、
  guard，以及语言本身。守卫在运行时执行的规则，和验证器证明的是同一个文件。
* **完备性阈值**（`eleph/threshold.py`）。`check` 从有界搜索变成了判定过程。线性阈值覆盖
  原子片段；在此之外完备性来自监视器的状态空间，再往外验证器会承认这次运行不是穷尽的。
* **过去的恒定时间求值**（`eleph/incremental.py`）。一步递推加上一条局部性引理。实测
  140,546 个事件用时 5.7 秒且吞吐平稳，而重读日志是平方的。`Machine(audit=True)` 会在每次
  查询时用日志核对索引。
* **持久的只追加日志**（`eleph/store.py`）。承诺被记录为事件，所以账本是推导而来的，不是
  被快照的。末尾被截断的一行会被丢弃，而日志仍然可用。
* **sort 与量化。** 带类型的参数、`exists P: Sort where`，以及 `count P: Sort where` ——
  容量上限需要的正是后者。
* **关于未来的承诺。** `promise C eventually φ` 和 `promise C that φ before e(...)`，带
  静态的可兑现性检查，以及一份报告哪些未清偿、哪些已违背的运行时账本。
* **言语行为作为可查询的谓词**（`spoke accept to C about e(...)`）。
* **自然语言边界**（`eleph/frontend.py`）。模型填写的那份 JSON schema 是从程序自己的处理器
  生成的。
* **线程安全。** 并发写入者会被串行化。
* **τ-bench 审计**（`bench/taubench/`）。确认规则和取消资格规则，在 200 条已发表轨迹上
  重放。
* 原子片段的 **NP 完全性**，附带一份对照暴力枚举实际运行、而不只是被宣称的 SAT 归约。
* 命令：`obligations`、`check`、`run`、`talk`、`ledger`。
* 英语、葡萄牙语、西班牙语和中文文档。

### 变更

* 从 `elephant2000` 更名为 `eleph`。
* 阈值改为按义务计算，而不是固定上界六。那个上界是**不可靠的**：`examples/fundo.eleph`
  要到第七个事件之后才说谎，而上界六会通过它。
* 阈值改为对每个不同原子取最大需求求和，而不是按语法节点。阈值降到约三分之一，测试套件也
  变快了。

### 修复

* Z3 维护一张全局符号表，所以现在每一次编码都用自己的命名空间。没有这一点，某个 sort 上
  声明的名字会和下一个冲突。
* 账本不再在每个事件上重新扫描所有承诺 —— 那件事即便在有索引之后仍让运行时保持平方复杂度。
* sort 标签不再冲突（`Party` 和 `Passenger` 都以 `p` 开头），那曾让两个 sort 在反例里无法
  区分。
* 未来承诺的可兑现性现在要求存在一条把它由假变真的路径。此前的检查接受任何可满足的公式，
  因而是空洞的。
