## 唯一的一条规则

<Callout type="danger" title="不要发布一个你没有亲手核对过的数字。">
本仓库里每一条定量主张都经受过对个别案例的审计，而且**其中三条因此改变了**。第一次统计
未确认写入时，把一批操作算在了一个 `yes` 名下。第二次把「先升舱再取消」判成了违规，而策略
明确允许这样做。第三次用「发生过一次」去建模一个可变属性。每一次修正都让数字**更小**，让
主张更强。

如果你新增一项度量，请连同支撑它的人工审计一起加上，并在 docstring 里写清你核对了什么。
</Callout>

## 什么算是一个好的改动

* **一个没有它就会失败的测试。** 这里的测试是论证，不是杂务。
  <Source file="tests/test_soundness.py" /> 和 <Source file="tests/test_incremental.py" />
  存在的意义就是去推翻代码库别处作出的主张；那就是应该照抄的形态。
* **一条诚实的局限，如果这个改动带来了的话。** [诚实的局限](/docs/limits)那份清单不是
  营销上的含糊其辞。它经过验证，其中每一条都在那里是因为确实有东西没有被覆盖。**往里面添
  东西本身就是一项贡献。**
* **说「为什么」而不是「是什么」的注释。** 读这些代码的人，是在决定要不要信任它。

## 需要帮手的地方

| 在哪 | 做什么 | 规模 |
|---|---|---|
| **Lean 4** | 把两条定理机器化，范围限定在 ground 片段。mathlib、Rocq 或 Isabelle 里都没有可以移植的东西，所以据我们所知，这将是**第一份为时态规约语言机器化验证的完备性阈值**。 | 五到九个工作日 |
| **挂钟时间** | `since_not` 知道顺序，不知道时间。带时间戳的事件加上区间比较，需要重做完备性论证。 | 研究级，不是一个周末 |
| **事件里的数据** | 如果谓词是按事件划分的，带类型的负载字段能在末次出现抽象下存活，但 Z3 编码和阈值都还需要工作。 | |
| **更多 τ-bench 规则** | 按等级和舱位划分的行李额度是显而易见的下一条。 | |
| **快照** | 打开一份一千万事件的日志会重放全部一千万。一份可以被**核对**而不是被信任的快照，可以保住那条「推导而来」的性质。 | |

## 风格

跟着周围的代码走。**面向用户的命令行字符串用葡萄牙语，标识符、docstring 和注释用英语。**
不要使用破折号字符。

## 发布版本

推一个 tag 就会发布。`.github/workflows/release.yml` 负责这件事，而它做的大部分事情是拒绝
发布。

```bash
# 1. 改那个唯一的真值来源
$EDITOR pyproject.toml        # version = "0.4.0"

# 2. 写清改了什么
$EDITOR CHANGELOG.md

# 3. commit、打 tag、推送
git commit -am "chore: release 0.4.0"
git tag -a v0.4.0 -m "eleph 0.4.0"
git push origin main --tags
```

然后这个 workflow 会按顺序核对：

<Steps>
<li>tag 与 `pyproject.toml` 一致；</li>
<li>这个版本从未被发布过 —— PyPI 永远不允许一个版本被替换或复用，所以这是能抓住它的最后
时刻；</li>
<li>测试在支持的最旧和最新解释器上都通过；</li>
<li>产物格式正确；</li>
<li>构建出的 wheel 能装进一个干净环境，并且仍然能证明和拒绝正确的那些程序。</li>
</Steps>

只有到这时它才会上传，并切出一个附带产物的 GitHub release。

<Callout type="note" title="那份清单里的 3.11 不是走过场">
唯一一个进入过已发布版本的 bug，是一个只有 3.11 会看到的语法错误。
</Callout>

`__version__` 是从已安装包的元数据里读的，而不是被第二次写下来。一个在两个文件里重复的
版本号，早晚会在某次发布里悄无声息地与自己不一致。

### 配置

这个 workflow 需要一个仓库 secret，`PYPI_API_TOKEN`，**作用域限定在这个项目而不是整个
账号**。它运行在一个名为 `pypi` 的 GitHub environment 里，所以如果上传需要人工批准，可以
在那里加上必需的审阅者。

要在不发布任何东西的情况下演练一遍，可以从 Actions 页签手动运行这个 workflow 并保持
`dry_run` 勾选：除了上传，其他一切都会发生。

如果你宁愿完全不保存 token，trusted publishing 是更好的安排，它会把那个 secret 换成一次
OIDC 交换。

## 这个文档站

站点在 <Source file="site" /> —— Vite、React 和 MDX，部署在 Vercel。内容是
`src/content/<locale>/` 下每页一个 MDX 文件，侧边栏是 `src/lib/nav.ts`：一个页面不可能
存在却无法到达，也不可能可以到达却不存在。

本站每一段终端输出都是一次真实的运行，原样粘贴。如果你改变了命令行产生的输出，引用它的
那些页面需要重新粘贴，而不是编辑。

```bash
cd site
npm install
npm run dev
```
