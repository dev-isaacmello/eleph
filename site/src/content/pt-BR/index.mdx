# O que é o eleph

<p className="lede">
O eleph é uma linguagem de programação para a parte do sistema que fala. Ela tem
atos de fala no lugar de comandos de impressão, um histórico no lugar de
variáveis, e condições de correção que são lidas do programa em vez de escritas
ao lado dele.
</p>

Ela implementa e estende o **Elephant 2000**, uma linguagem especificada por John
McCarthy em Stanford, em 6 de novembro de 1998, e nunca implementada por ele. O
projeto é dele. Os limiares de completude, as obrigações de compromisso, o
runtime incremental e a API embutível são deste projeto.

## O problema para o qual ela foi construída

Um agente afirma coisas sobre o registro de um cliente, e promete fazer coisas.
Hoje nada liga nenhum dos dois à realidade. Filtros de saída conferem o texto.
Nada confere se uma afirmação decorre do que de fato aconteceu, e nada acompanha
se uma promessa chegou a ser cumprida.

A resposta de McCarthy, escrita antes de o problema existir: faça o programa
dizer apenas o que o próprio histórico dele sustenta, e faça das promessas
dívidas que ele tem que quitar. Duas obrigações, ambas dele:

* **Uma resposta tem que ser verdadeira.** Todo `yes` ou `no` tem que ser
  implicado pelo log.
* **Uma promessa tem que ser cumprida.** O programa não pode prometer o que o
  histórico dele não estabelece, nem prometer o que nenhum caminho por ele
  jamais conseguiria realizar.

Você não escreve essas condições. O compilador as lê do programa.

```out
$ eleph obligations examples/airline_buggy.eleph

  linha 17  question(Caller, has_reservation)
    resposta yes e verdadeira
      supondo   alguma vez make_reservation(P, F)
      entao     (make_reservation(P, F) e desde entao nenhum cancel_reservation(P, F))
```

Depois ele tenta quebrá-las.

<Callout type="note" title="O CLI fala português">
O `eleph` imprime em português. Esse é o idioma do autor e a saída faz parte do
artefato, então este site a cita literalmente. Todo bloco de terminal aqui é uma
execução real.
</Callout>

## O que ele não é

Não é uma técnica de prompt, um filtro de saída, nem um motor de políticas que
se configura. É uma linguagem pequena com um verificador, mais uma biblioteca
que você pode colocar embaixo de um sistema Python existente sem adotar a
linguagem em nada.

Também não está pronto. A página de [limites honestos](/docs/limits) é
verificada e não é hedge de marketing: não existe relógio de parede, agregados
sobre o histórico não são expressáveis, fatos não podem ser recursivos, e os
dois teoremas são provados no papel e testados, não mecanizados.
